## Introdução

<p align = "justify">
    O 5W2H descreve o planejamento do projeto AAC_Refeito, um backend Django para gerenciar Atividades Acadêmicas Complementares com perfis de aluno, coordenador e organização.
</p>

## Metodologia

<p align = "justify">
    A equipe mapeará o código atual em `src/backend/AAC_Refeito` para alinhar os objetivos do projeto com as funcionalidades implementadas: autenticação, cadastro de atividades, aprovação e validação de horas.
</p>

## Questões 5W2H

### Visão do Produto

|Questão|Resposta|
|---|---|
|What? (O que será feito?)|Desenvolvimento de um backend em Django e Django REST Framework para gerenciar Atividades Acadêmicas Complementares, com APIs e dashboards simples.| 
|Why? (Por que isso será feito?)|Para facilitar o registro, validação e acompanhamento de horas complementares em um único sistema.| 
|Where? (Onde será feito?)|No módulo `src/backend/AAC_Refeito`, com rotas web em `core.urls` e API em `core.api_urls`.| 
|When? (Quando será feito?)|Durante o semestre de 2026, com documentação finalizada para `mkdocs gh-deploy`.| 
|Who? (Quem irá fazer?)|Equipe de desenvolvimento composta por Miguel, Maria Luisa e Bento.| 
|How? (Como será feito?)|Usando Python, Django, DRF, HTML/CSS e documentação MkDocs; o trabalho será gerenciado via Git.| 
|How Much? (Quanto custará?)|O investimento é principalmente em horas de trabalho e revisão do projeto, sem custo adicional de infraestrutura na fase atual.| 

## Funcionalidades Principais

- Cadastro e autenticação de usuários com perfis: Aluno, Coordenador e Organização Acadêmica.
- Registro de atividades externas pelo aluno.
- Cadastro de atividades internas por coordenador ou organização.
- Aprovação e reprovação de atividades externas pelo coordenador.
- Cálculo de horas integralizadas aprovadas e painel de controle para o aluno.
- API REST para gerenciar usuários, atividades e validações.

## Conclusão

O 5W2H demonstra que o AAC_Refeito é um projeto backend centrado na gestão de AACs, com foco em automação de processos e documentação para deploy. A documentação deve apoiar a entrega do código existente e facilitar o uso do sistema pelo público acadêmico.
